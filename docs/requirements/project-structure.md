# Project Structure Requirements - ShellParser

**Status**: Active (Version 1.0+)

## 1. Purpose

This document defines the official directory structure and organization rules for ShellParser to ensure clarity, maintainability, forking safety, and long-term anti-fragility.

## 2. Root Directory Structure (ShellParser Tool Itself)

```
ShellParser/                          # This repository / installed package
├── README.md
├── LICENSE
├── CHANGELOG.md
├── SECURITY.md
├── CIAO-PRINCIPLES.md
├── pyproject.toml
├── docs/
│   └── requirements/                 # All granular requirement documents
├── src/
│   └── ShellParser/
│       ├── __init__.py
│       ├── __main__.py
│       └── cli.py                    # Main implementation (ShellParserCore)
├── tests/                            # Test scripts and sample shell files (future)
└── .gitignore
```

**Important**: The `target/` folder is **NOT** part of the ShellParser tool itself.

## 3. Generated Output Structure (In Target Project)

When you run ShellParser against a shell script, it creates the following structure **in the root directory of the target project** (where the source `.sh` file lives):

```
{target-project-root}/
├── myscript.sh                       # Your original monolithic script
├── target/                           # Generated by ShellParser (gitignored)
│   ├── components/                   # Classic split output (*.sh files)
│   ├── docs/                         # LLM-friendly markdown output (*.md) — v2.0
│   └── report/                       # Stage 1 classification reports
├── myscript.sh.20260510-1            # Automatic backups (dated)
└── ...
```

## 4. Key Directory Rules

- **`target/`** is always created **relative to the source shell script** being processed.
- **`target/components/`** — Output of `split` command (`*.sh`)
- **`target/docs/`** — Output of `split-docs` command (`*.md` for LLM training)
- **`target/report/`** — Debug/classification reports
- `target/` must be listed in `.gitignore` of the target project.

## 5. File Naming Conventions

- Source files (ShellParser): `snake_case.py`
- Requirement files: `kebab-case.md`
- Generated components: `<function_name>.sh`
- Generated docs: `<function_name>.md`
- Backups: `<original>.YYYYMMDD-N`

## 6. Milestones Alignment

- **Version 1.0+**: Current structure stabilized
- **Version 2.0**: `target/docs/` fully supported
- **Version 3.0**: Semantic extraction support
- **Version 4.0**: Database integration

## 7. Forbidden Practices

- Committing `target/` folder into any project’s git repository
- Hard-coding absolute paths to `target/` (always relative to source file)
- Creating output files outside the `target/` tree
- Placing requirements documents outside `docs/requirements/`

## 8. Design Principles (CIAO-Lite)

- **Caution**: Clear separation between tool source and generated user project content
- **Intentional**: `target/` is always local to the user’s script being parsed
- **Anti-fragile**: Easy to ignore in git; safe for large monorepos
- **Over-protect**: Structure is protected to survive repeated AI-assisted development

## 9. Protection Rule (Sacred)

**Future AI or developers MUST NOT**:
- Move or rename core directories in the ShellParser tool (`src/ShellParser/`, `docs/requirements/`)
- Create `target/` inside the ShellParser package itself
- Hard-code any output paths (must be relative to the processed source file)
- Remove or weaken the rule that `target/` belongs to the **target project**
- Commit generated `target/` content to git
